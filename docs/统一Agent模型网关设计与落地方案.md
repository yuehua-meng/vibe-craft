# 统一 Agent 模型网关：9 人团队简版

日期：2026-10-02  
状态：设计文档，尚未开发部署。

## 1. 我们要解决什么

所有 Agent 项目共用一个模型入口，由一位管理员维护供应商 Key。Key 失效、账户没余额或接口暂时异常时，网关按规则切换备用；员工继续在各自项目中操作。

第一版只做五件事：**统一接入、主备切换、超时重试、简单用量控制、错误记录。**

## 2. 用最小架构落地

```text
9 位员工 → 各自使用的 Agent 项目
                    ↓ 项目独立访问凭据
             统一网关 FastAPI
             ├─ 配置文件：主备模型与调用规则
             ├─ .env：供应商 Key、项目访问凭据
             ├─ SQLite：调用记录、用量、操作状态
             └─ httpx → 主账户 / 备用账户 / 备用供应商
```

沿用当前项目熟悉的 **Python + FastAPI + httpx + SQLite**，网关放在独立的 `agent-gateway` 目录，一台常开机器、一个进程运行。通过内网或 VPN 访问，跨机器调用启用 HTTPS。进程设置自动重启，每天使用 SQLite 在线备份方式保存数据库。

第一版不需要 Redis、PostgreSQL、微服务、消息队列或复杂权限后台。并发控制放在单进程内，调用状态保存在 SQLite。容量按实际模型配额与并发验证，不单凭团队人数判断。

每个项目分配一个独立访问凭据，员工不用接触供应商 Key。管理员修改配置或换 Key 后，等待在途请求结束再重启网关。密钥文件只允许运行账号和管理员读取，不提交 Git，不进入日志。

## 3. 必做功能和规则

| 功能 | 第一版怎么做 |
|---|---|
| 统一模型入口 | 项目只配置网关地址、项目凭据、模型别名 |
| 主备配置 | 每类模型配置一个主候选、一个备用候选 |
| Key 失效 | 停用该 Key，改用有效备用；状态持久化 |
| 上游余额不足 | 停用整个共享余额账户，切换独立余额的备用账户 |
| 临时限流或服务异常 | 有限重试或切换，失败后向项目返回明确原因 |
| 用量控制 | 项目日调用次数上限、单次输出长度上限、全局并发限制 |
| 调用记录 | 记录项目、任务、实际模型、耗时、尝试次数、错误和估算费用 |
| 简单状态页 | 管理员查看主备可用状态、各项目今日用量、最近失败；不显示密钥 |

**同一个账户的两个 Key 通常共用余额，不能把换 Key 当作换账户。** 余额不足须依据供应商明确错误码判断，不能把所有 429 都当作没钱。

初期不做自动余额查询或自动充值。确认余额不足后在状态页提示，管理员充值并验证成功后恢复。没有有效备用时明确报错，不无限重试。

## 4. 模型只分三类

| 别名 | 当前项目用途 | 备用要求 |
|---|---|---|
| `text.default` | 文章、摘要 | 支持所需文本长度；摘要请求需要 JSON 输出 |
| `text.vision` | 根据商品原图生成选题 | 支持图片输入和 JSON 输出 |
| `image.default` | 参考商品原图生成配图 | 支持图生图、多参考图及要求的尺寸 |

优先使用同一模型的备用账户。跨供应商切换前，用真实业务样例验证输出格式和质量；没验证的模型不加入备用列表。方舟专属参数在网关中转换，不直接原样转发给其他供应商。

后续其他 Agent 需要工具调用时，再为它增加相应能力检查。演示 Mock 模式继续独立存在，不用于真实调用失败后的自动兜底。

## 5. 超时重试：规则固定，避免越重试越贵

### 文本与视觉理解

- 连接超时起步设为 5 秒，单次尝试最长 50 秒，整次请求最长 120 秒；上线后按实际耗时调整。
- **首次调用、重试、主备切换合计最多 3 次**，排队与等待也包含在 120 秒内。
- 临时网络异常、429 限流和 5xx 可重试；等待约 1 秒、2 秒并加随机抖动。有 `Retry-After` 时遵守该时间，或切到独立配额的备用。
- 参数错误不重试；Key 失效、明确没余额直接停用相应候选；内容拒绝不自动换模型。
- 只有网关自动重试，业务项目和底层客户端关闭额外自动重试。读取超时可能已经计费，所有尝试都记录。
- 某候选连续 3 次临时失败，暂停使用 60 秒，再放行一次探测。余额不足和 Key 失效必须由管理员验证恢复。
- 第一版先支持当前项目使用的非流式调用；未来增加流式时，输出开始后断线不得拼接备用模型结果。

### 生图

单次等待上限先沿用当前项目的 240 秒。仅在**确定未提交或明确被上游拒绝受理**时允许切换一次备用。

如果超时、发送后断线，或网关重启时发现有未完成提交，将该操作标记为“结果待确认”。先查询供应商记录；不支持查询时由管理员核对。员工明确选择重新生成后才再次提交，并提示可能重复扣费。

生图操作使用 `项目 + 任务 + 平台 + 节点 + 输入版本 + 生成序号` 作为唯一标识，发送前写入 SQLite。同一操作重复请求只返回已有状态或结果；相同标识但内容不同则拒绝。主动重新生成才增加生成序号，避免双击、断线重发或工作流恢复造成重复生图。

网关返回结果前保存结果引用；即使客户端已经断开，也尽量记录最终状态。进程崩溃造成的未知结果仍须核对，不能仅凭本地记录保证上游只扣费一次。

## 6. 费用与并发：先做简单有效的约束

初始全局并发建议：**文本 5 个、生图 2 个**，按供应商实际配额调低或调高。文本排队最多 2 秒，生图排队最多 5 秒；超出返回忙碌提示。第一版不建设后台任务队列。

每个项目设置日调用次数上限和单次输出上限。日计数按北京时间计算，使用 SQLite 事务检查并占用额度，**每次上游尝试均计数**；达到上限就停止，切换账户也不能绕过。

费用先做估算展示，按实际模型和版本化价格累计，缺失 usage 的请求标记“费用待核对”。可以配置月度费用提醒，但它不是严格的实时金额封顶。需要限制真实支出时，同时使用供应商提供的消费限制或有限预充值余额。

管理员状态页只保留三块：账户状态、项目用量、最近错误。日志保留 30 天，默认不记录提示词、原图、完整回答和密钥；状态页使用独立管理凭据访问。

## 7. 当前图文项目怎么接

项目配置改为：

```dotenv
LLM_GATEWAY_BASE_URL=https://gateway.example.internal/v1
LLM_GATEWAY_API_KEY=<当前项目独立凭据>
LLM_TEXT_MODEL=text.default
LLM_VISION_MODEL=text.vision
LLM_IMAGE_MODEL=image.default
```

需要改动四处：

1. `app/config.py`：读取网关地址、项目凭据及模型别名。
2. `app/providers.py`：增加 `GatewayProvider`，保留现有提示词、图片处理和业务 JSON 校验。
3. `app/main.py`：配置检查改为识别网关；返回可理解的余额、限流、超时和待核对提示。
4. `app/workflow.py`：传递任务和节点标识，保存生图操作 ID；恢复时查询原操作。人工重新生成创建新序号。

接口只覆盖实际需要的范围：`POST /v1/chat/completions`、`POST /v1/images/generations`、`GET /operations/{id}`、`GET /health` 和管理状态页。生图 POST 正常时直接返回结果，处理中或结果未知时提供操作查询入口；所有查询都校验项目归属。

原有人工审核、三平台流程、SQLite 断点和导出功能继续使用。先迁移文本，验证稳定后再迁移生图。

## 8. 开发顺序与验收

| 顺序 | 交付内容 | 验收方式 |
|---|---|---|
| 1 | 独立网关、项目凭据、文本主备、统一重试、日志 | 模拟余额不足能切换；持续超时最多调用 3 次且总时限有界 |
| 2 | 日调用上限、并发控制、管理员状态页 | 并发请求不突破日次数；能看见实际使用的模型与错误 |
| 3 | 生图接入、操作去重与结果核对 | 重复点击不会重复提交；生图超时不自动再次扣费 |
| 4 | 当前项目跑通后，逐个接入其他 Agent | 原有业务流程通过；每个项目有独立凭据和调用记录 |

开始开发时需要准备：**当前要接入的项目清单、一个主账户、一个可用备用账户，以及各项目日调用上限。** 具体 Key 通过本地密钥配置提供，不写进文档。

第一版完成上述范围即可供团队试用；只有实际出现单机容量或稳定性问题时，再升级部署结构。
